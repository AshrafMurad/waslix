# M8.7 · Performance, security and production validation

## Scope

Validated the M8.7 release gate from `docs/11-IMPLEMENTATION-PLAN.md` and `docs/WASLIX-SPRINT-PHASES.md`: query/index review, Server/Client Component boundaries, authorization and workspace isolation, environment validation, build/security posture, dependency surface and error handling/logging foundation.

## Findings and fixes

| Area | Result |
| --- | --- |
| Query and index review | Prisma access uses workspace-scoped predicates on protected domain reads/writes. Existing indexes cover workspace/status/customer/owner/date access patterns for portfolio, tasks, risks, health, attention, renewals, imports and outbox. No M8.7 schema change required. |
| N+1 prevention | Current route projections use bounded `findMany`, selected fields and relation projections instead of per-row React fetch loops. No obvious N+1 regression found in the M8 query surfaces. |
| Server/Client boundaries | Pages remain Server Components by default; client files are limited to forms, tables, dialogs, shell controls and error boundaries. No Prisma/auth imports found in client components. |
| Authorization and workspace isolation | Protected paths follow authenticate, ACTIVE membership, capability/object check and workspace-scoped persistence. Search/import/analytics/work queues include workspace scope. No known cross-workspace access found. |
| Environment validation | Web, Prisma and worker entry points now share the Zod-backed server environment contract instead of ad hoc worker `process.env` checks. |
| Build/security posture | Production browser source maps remain disabled by default. Global security headers now set `Referrer-Policy`, `X-Content-Type-Options`, `X-Frame-Options` and a restrictive `Permissions-Policy`. |
| Dependency cleanup | `package.json` contains no obvious unused major framework dependency from the M8.7 review. The `cn` package is intentionally used by shadcn primitives and current UI code. No dependency changes made. |
| Error handling/logging | Locale-level error and not-found pages now provide safe translated fallbacks. Worker logs remain operational and avoid payloads, secrets and customer narratives. |

## Acceptance checks

- No known cross-workspace access remains from the reviewed protected paths.
- Production build/type checks must pass with centralized environment validation.
- No obvious performance regression or query waterfall was found in the reviewed M8 surfaces.
- No unnecessary major dependency was added or removed.

## Deferred to M8.8

Deployment smoke tests, Docker/Coolify configuration, web/worker readiness endpoints, migration release execution and database restore verification remain owned by M8.8.
